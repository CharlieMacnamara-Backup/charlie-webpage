The owner, Marty, hand-sews 12-yard kilts from memory. Three generations of
craft. He works alone in a showroom that hasn't changed much since his
grandfather's day: notepad by the phone, paper diary, appointment slips.

The methods were proven, but flawed. Calendar bookings misplaced, missed calls,
staying late to rewrite orders in three places. He was receptive.

His old site had been down for a couple of years. He was ready. We sat down and talked through what he needed.

I'd already built [Sicamon](https://sicamon.com) — a full Stripe CMS with
digital cataloguing. He wanted none of it. No online inventory, no card
payments. Bank transfers. What he's always done. This system works with that.

Every line of code had to be right. This isn't a side project that can go down
— it's a sole trader's livelihood. A failed booking is a missed fitting, a lost
sale, a customer who doesn't come back. So I tested relentlessly: Vitest for
fast unit tests, Playwright for end-to-end flows against the real Google
Calendar API. 324 tests across four workers. And the whole thing — Workers, D1,
KV, Turnstile, Resend, GitHub Actions — costs nothing to run.

The strongest identity of this business was heritage. A century in 2027 — I

### The Booking Pipeline

- **Bot detection** — <Definition term="turnstile">Turnstile</Definition>,
  invisible
- **Input validation** — malformed data rejected
- **Closure check** — reads `[Closed]` calendar events
- **Slot availability** — no double-booking
- **Event creation** — writes to Google Calendar
- **Cancel link** — signed <Definition term="jwt">JWT</Definition> in the event
- **Notifications** — <Definition term="async">async</Definition> emails to both
  customer and site owner, never blocks

<Definition term="deterministic">Deterministic</Definition>. Someone else books
the slot mid-form? You're told immediately.

Everything integrates into the existing Google Calendar. Closures are set by
adding `[Closed]` — Christmas, holidays, any day off. The site reads that
automatically.

## The Workers

### Frontend Worker

The shop window. Serves every page a visitor lands on — hero, map, services, the
tartan search widget, reviews, and the booking button. Static build, globally
distributed. No server to babysit.

### Calendar Worker

Looks after the booking system — a separate worker with its own credentials.
Reads `[Closed]` events, checks slot availability, writes new bookings, and
generates cancel links.

### Reviews Worker

Pulls Google Reviews on a schedule into
[KV](https://developers.cloudflare.com/kv/). Stays current without input — fresh
content, zero effort.

## The Admin Dashboard

The notepad replacement — its own
[Cloudflare Worker](https://workers.cloudflare.com/) backed by
[D1](https://developers.cloudflare.com/d1/). The same order in the diary, on a
slip, and on a sales pad — three times, one customer. Now it's a page.

Four statuses: In Progress, Ready, Delivered, Cancelled. Every transition logged
immutably — who changed it, when, and whether the email went out. Group orders
for wedding parties — groom, best man, ushers under one accordion. Measurements:
kilt waist, seat, length, jacket chest, sleeve, back, height, build notes. All
optional.

Emails fire on status changes via [Resend](https://resend.com/). The receipt
includes bank details — stored as Worker secrets, never in the codebase.
On creation the customer gets payment instructions. When it's ready, a
collection notice. Not a word typed. CSV export: current tax year, last
year, or custom range. Clean totals at the bottom for the accountant.

Quick Add for reconciling past orders. Archived orders auto-purge after 30 days.
No payments on-platform — bank transfer, cash, the till. Progress without
overwhelm.

[Google Calendar](https://calendar.google.com/) is the database — zero new

[Turnstile](https://www.cloudflare.com/products/turnstile/) over CAPTCHA for the
same reason: free, invisible, no learning curve. Cancel links use signed
<Definition term="jwt">JWTs</Definition> in the event description — no database
lookup. Email fires asynchronously so the booking never blocks on a delivery
failure. [Tailwind](https://tailwindcss.com/) keeps every layout consistent —
utility classes enforce a design system, no magic numbers. Typography scales
fluidly with CSS `clamp()` — no breakpoint jumps, no layout surprises.

## Testing

Every worker has deterministic tests that mock external APIs and validate
internal logic. Then live tests hit the real Google Calendar, Resend, and
Turnstile APIs. A pre-deploy script runs static audit rules to catch hardcoded
secrets and broken contracts. A health check probes all four workers every six
hours.

I'm a message away if a fix is needed. The binder is back on the shelf. And the
marquee with qualitykilts.com is still there — now it works.
